## یافته قطعی: اختلاف منابع قیمت

فهرست موردتأیید پروژه:
1. Nobitex
2. Wallex
3. Bit24
4. Kifpool

اما تابع فعلی فقط این providerها را فراخوانی می‌کند:
- `fetchNobitex()`
- `fetchWallex()`
- `fetchBitpin()`

در نتیجه:
- Bit24 در مسیر قیمت تومانی فعلی وجود ندارد.
- Kifpool در مسیر قیمت تومانی فعلی وجود ندارد.
- Bitpin به‌عنوان منبع اضافی فعلی استفاده می‌شود و جایگزین دو منبع تأییدشده نیست.

رابط نیز در پیام وضعیت `refreshTomanMarket()` صریحاً می‌گوید قیمت از «نوبیتکس، والکس و بیت‌پین» دریافت می‌شود. بنابراین اختلاف فقط در Edge Function نیست؛ متن وضعیت صفحه هم همین سه منبع را منعکس می‌کند.

نکته: تابع جداگانه `sync-iran-exchange-assets` برای کشف فهرست دارایی‌ها Bit24 و Kifpool را می‌شناسد. این مشاهده‌های فهرست بازار، داده قیمت قابل معامله/قابل نمایش نیستند و نباید بدون تطبیق واحد قیمت، نماد و نوع دارایی به جدول قیمت تومانی منتقل شوند.

## شواهد درخواست‌های Edge Function در ۲۴ ساعت منتهی به ۲۰۲۶-۱۱-۲۲ ۱۰:۳۴ UTC

| نوع درخواست | تعداد | نتیجه |
|---|---:|---|
| OPTIONS | ۲۵ | HTTP 200 |
| POST | ۲۵ | HTTP 502 |

آخرین POST ناموفق در `2026-11-22T09:20:59Z` ثبت شده است. لاگ gateway کد ۵۰۲ را نشان می‌دهد، اما بدنه پاسخ و خطای داخلی هر provider در لاگ‌های قابل‌دسترسی ثبت نشده؛ بنابراین علت دقیق هر ۵۰۲ را نمی‌توان با اطمینان به یک صرافی یا مرحله نوشتن دیتابیس نسبت داد.

کد فعلی در صورت نبود هیچ ردیف معتبر از providerها، پاسخ ۵۰۲ می‌دهد؛ همچنین خطای بیرونی هنگام خواندن cache یا نوشتن دیتابیس نیز می‌تواند ۵۰۲ ایجاد کند. این دو مسیر باید با لاگ ساختاریافته و آزمون fixture از هم تفکیک شوند.

## رفتار فعلی رابط

- تب «بازار تومانی» هنگام بازشدن، `market_toman_performance` را می‌خواند.
- اگر ردیف تازه نداشته باشد، تابع refresh را فراخوانی می‌کند.
- تا زمانی که تب باز است، refresh خودکار هر پنج دقیقه تکرار می‌شود.
- خطای invoke در `tomanMarketStatus` به کاربر نمایش داده می‌شود.
- جدول‌های قیمت خالی‌اند؛ پس صفحه نمی‌تواند قیمت واقعی تومانی از این منبع نشان دهد، حتی اگر داده کشف بازار در جدول observation موجود باشد.

## گام اجرایی بعدی

1. قرارداد رسمی/پاسخ نمونه Bit24 و Kifpool را بدون نوشتن در دیتابیس بررسی و فیلدهای قیمت، bid/ask، حجم و واحد را مستند کن.
2. adapterهای مستقل برای هر چهار منبع بساز؛ برای Kifpool تطبیق با کاتالوگ رمزارز و حذف دارایی‌های سهامی/توکنیزه‌شده الزامی است.
3. fixtureهای پاک‌سازی‌شده و آزمون‌های واحد برای هر provider، تبدیل ریال/تومان، stale data، پاسخ ناقص، timeout و خطای یک منبع در کنار موفقیت منابع دیگر اضافه کن.
4. logging ساختاریافتهٔ نتیجه هر provider و مرحله ذخیره‌سازی اضافه کن تا ۵۰۲ بعدی علت قابل‌تشخیص داشته باشد.
5. ابتدا در CI/محیط ایزوله آزمون کن. استقرار نسخه جدید Edge Function روی Production یک تغییر زنده است و تا تأیید صریح کاربر انجام نشود.

## پیگیری فقط‌خواندنی و اصلاح کد — ۲۳ نوامبر ۲۰۲۶
- قید یکتای جدول جاری دقیقاً `(exchange, asset_symbol, quote_currency)` است؛ تابع نسخه ۳ درخواست POST را بدون `on_conflict` می‌فرستاد. تکرار همان کلیدها با درج ساده تعارض دارد.
- snapshot تازه: ۳۷۳ ردیف در جدول جاری و ۳۷۳ ردیف تاریخچه؛ آخرین زمان هر دو `2026-11-17 22:04:26 UTC`. این داده‌ها stale بودند.
- در ۲۴ ساعت منتهی به `2026-11-22 23:14 UTC`، ۲۱ POST با HTTP 502 و ۲۱ OPTIONS با HTTP 200 ثبت شد. این قید یکتا و POST ساده یک علت قطعی و بازتولیدپذیر برای شکست تکرار batch است؛ خطاهای provider مستقل نیز ممکن است هم‌زمان وجود داشته باشند.
- کد GitHub اکنون upsert با conflict target دقیق، dedupe درون batch، و logging ساختاریافته بدون داده حساس دارد. آزمون‌های Node و fixture PostgreSQL 17 با transaction/rollback به CI اضافه شدند.
- Production همچنان Edge Function نسخه ۳ را اجرا می‌کند. هیچ deploy، refresh واقعی یا تغییر داده‌ای انجام نشد؛ استقرار تا تأیید صریح کاربر متوقف است.
